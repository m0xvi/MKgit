# MikroGit — бэкап и обновление устройств MikroTik через Telegram-бота

Набор bash-скриптов для Ubuntu-сервера:

- `MikroGit.sh` — резервное копирование конфигураций RouterOS по SSH
  (файлы `.rsc` кладутся в `bckp/<device_name>/`).
- `tg/mk_tg_bot.sh` — Telegram-бот (поллинг + inline-клавиатуры).
- `tg/mk_updates.sh` — **проверка, скачивание и установка обновлений RouterOS**
  с уведомлениями в Telegram (новая функция).

## Устройства

Файл `devices.conf`, формат строки:

```
имя:ip:порт:ssh_user:описание
```

Пример:

```
GW_DONA:10.10.0.1:22:admin:Шлюз Дона
office_router:192.168.1.1:22:admin:Офис
```

## Установка на Ubuntu-сервер

```bash
git clone https://github.com/m0xvi/MKgit.git
cd MKgit
cp tg/tg_bot_config.sh.example tg/tg_bot_config.sh
chmod +x MikroGit.sh tg/*.sh
```

Заполните `tg/tg_bot_config.sh` (токен бота, chat_id, пути, прокси).
Затем:

```bash
chmod 600 tg/tg_bot_config.sh          # конфиг содержит токен
mkdir -p ~/.ssh && ssh-keygen -t rsa -b 4096 -f ~/.ssh/mk_key -N ""
# Добавьте ~/.ssh/mk_key.pub в /user ssh-keys на каждом MikroTik
# (или запустите start_bot_with_ssh.sh, который покажет публичный ключ)
```

Запуск бота (в tmux/systemd или руками):

```bash
cd tg
./start_bot_with_ssh.sh        # поднимает ssh-agent и запускает бота
```

Резервные копии по расписанию (пример cron):

```
0 3 * * * /home/USER/MKgit/MikroGit.sh --telegram auto >> /home/USER/MKgit/logs/mk_backup.log 2>&1
```

## Обновления RouterOS через бота

Механика:

1. **Проверка** выполняется через сам роутер:
   `/system package update check-for-updates`.
   Бот определяет ветку автоматически (RouterOS 6 → 6.x, RouterOS 7 → 7.x)
   и обновляет **в рамках своей ветки** (кросс-апгрейд 6→7 не выполняется).
2. **Установка** — только после вашего подтверждения в Telegram:
   - создаётся резервная копия конфигурации (`MikroGit.sh --device ...`);
   - на роутер отправляется `/system package update download`;
   - после скачивания роутер **перезагружается** (~2–5 мин недоступности);
   - бот ждёт возвращения устройства и присылает итоговую версию.
3. Если после обновления RouterBOOT firmware новее RouterOS — бот подскажет,
   что `/system routerboard upgrade` стоит сделать вручную.

### Кнопки и команды

- В главном меню: **«⬆️ Обновления RouterOS»**
- Команды: `/updates`, `/checkupdates`
- В меню обновлений:
  - **«Проверить сейчас (все)»** — проверка всех устройств;
  - **«Последний статус»** — результат последней проверки из кеша.
- После проверки бот присылает отчёт, а при наличии обновлений — кнопки
  «Установить: <device>» → подтверждение → установка.

### Автопроверка по расписанию

Бот сам запускает проверку всех устройств каждые `UPDATE_AUTO_INTERVAL_HOURS`
(по умолчанию 24 ч) и присылает отчёт. Управляется переменными:

```bash
export UPDATE_AUTO_CHECK="1"               # 1/0
export UPDATE_AUTO_INTERVAL_HOURS="24"     # интервал автопроверки
```

### Настройки обновлений (tg/tg_bot_config.sh)

| Переменная | По умолчанию | Описание |
|---|---|---|
| `UPDATE_CHANNEL` | `stable` | Канал: `stable`, `long-term`, `testing` или `""` (не менять канал роутера) |
| `UPDATE_BACKUP_BEFORE_APPLY` | `1` | Бэкап конфигурации перед установкой |
| `UPDATE_DOWNLOAD_TIMEOUT` | `900` | Таймаут скачивания, сек |
| `UPDATE_REBOOT_WAIT` | `600` | Ожидание возврата после перезагрузки, сек |
| `UPDATE_REBOOT_POLL` | `10` | Пауза опроса после перезагрузки, сек |
| `UPDATE_SSH_TIMEOUT` | `60` | Таймаут короткой SSH-команды, сек |
| `UPDATE_CHECK_TIMEOUT` | `150` | Таймаут `check-for-updates` (доступ роутера к upgrade.mikrotik.com) |
| `UPDATE_AUTO_CHECK` | `1` | Автопроверка по расписанию |
| `UPDATE_AUTO_INTERVAL_HOURS` | `24` | Интервал автопроверки, часы |

### Запуск проверки/установки вручную (без бота, например из cron)

```bash
export HOME=/home/USER
source tg/tg_bot_config.sh
source tg/tg_api_helpers.sh          # прокси-обёртки для Telegram
bash tg/mk_updates.sh check all      # проверить все устройства
bash tg/mk_updates.sh check GW_DONA  # проверить одно
bash tg/mk_updates.sh apply GW_DONA  # установить обновление (подтверждение не нужно — осторожно!)
bash tg/mk_updates.sh status         # отчёт из кеша последней проверки
```

> ⚠️ `apply` запускает скачивание + перезагрузку роутера **без** Telegram-подтверждения.
> При ручном запуске из cron вы сами отвечаете за окно обслуживания.

## Права пользователя MikroTik (важно!)

Проверка обновлений выполняется от SSH-пользователя из `devices.conf`, и он
должен иметь **права на изменение конфигурации и перезагрузку**, а не только
на чтение. Если у пользователя мало прав — `check-for-updates` вернёт ошибку
(«not enough permissions»), а установка не запустится.

Минимальный набор политик группы (`/user group`):

- `ssh` — вход по SSH;
- `read` — чтение конфигурации и `/system resource print`;
- `write` — нужна для `/system package update set/check/download`;
- `test` — доступ к сетевым проверкам, которые использует обновление;
- `reboot` — чтобы бот мог перезагрузить роутер для установки;
- `ftp` — нужен, если бэкап MikroGit забирает файлы с роутера через scp/sftp.

Пример, как создать отдельную группу и выдать её пользователю (на каждом
роутере, команды из его консоли):

```
/user group add name=backup-update policy=ssh,read,write,test,reboot,ftp \
    comment="MikroGit backup + RouterOS update"
/user set [find name=ИМЯ_ПОЛЬЗОВАТЕЛЯ] group=backup-update
```

Самый простой (но менее безопасный) вариант — группа `full`. Политики `policy`,
`sensitive`, `password` для этой задачи не нужны.

Проверить текущую группу пользователя:

```
/user print detail where name=ИМЯ_ПОЛЬЗОВАТЕЛЯ
```

## Почему проверка может идти долго (и что делать)

- Устройства проверяются **последовательно по одному** — по каждому бот
  присылает отдельное сообщение `⏳ [n/N] устройство…`, затем результат.
- На каждую SSH-команду есть таймаут (`UPDATE_SSH_TIMEOUT`, `UPDATE_CHECK_TIMEOUT`),
  поэтому одно «зависшее» устройство не блокирует остальные — оно получит
  статус ⚠️ и проверка пойдёт дальше.
- Если все роутеры долго «молчат» — вероятно, у них **нет доступа к
  `upgrade.mikrotik.com`** (серверы MikroTik недоступны/заблокированы). Тогда
  каждое устройство отработает по таймауту (~2,5 мин) и будет помечено ошибкой.
  Проверьте вручную с одного роутера:
  ```
  /system package update check-for-updates
  /ping upgrade.mikrotik.com
  ```
- При проблемах смотрите лог бота: `tail -f logs/mk_backup.log` — там видно
  `UPDATE: check <имя> -> …` по каждому устройству.
- Если сообщение «Запускаю проверку…» появилось, но воркер не стартовал —
  бот теперь сам пришлёт ⚠️ «Фоновая проверка не запустилась» со ссылкой на лог.

## Важные замечания

- Обновления качаются **самим роутером** с серверов MikroTik
  (`upgrade.mikrotik.com`). Если роутер их не видит (например, ограничения
  провайдера/РФ), проверка вернёт ошибку — тогда обновление этим способом
  невозможно (потребуется ручная установка `.npk`).
- Перед установкой всегда делается резервная копия конфигурации — но она не
  является откатом версии RouterOS (откат возможен только downgrade-пакетом
  вручную). Обновляйте прод-устройства в окно обслуживания.
- Конфигурация (`tg_bot_config.sh`), `devices.conf`, `bckp/` и `logs/` не
  попадают в git (см. `.gitignore`).
